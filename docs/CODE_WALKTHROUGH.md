# Academyflo — Code Walkthrough: `apps/api` & `apps/mobile`

> Generated from a full read of every source file in both apps (972 files: ~57k LOC API, ~71k LOC mobile).
> Coverage: 42 vertical slices (23 API + 18 mobile + shared contracts). Findings: **18 high, 82 medium, 167 low**.

---

## 1. The system at a glance

Academyflo is a **multi-tenant academy-management SaaS**. A *tenant* is an "academy" (a sports/coaching institute). Three tenant roles — **OWNER**, **STAFF**, **PARENT** — plus a platform-level **SUPER_ADMIN** that crosses tenant boundaries.

| | `apps/api` | `apps/mobile` |
|---|---|---|
| Stack | NestJS 11, Mongoose 9 (MongoDB), JWT, Cashfree PG, firebase-admin (FCM), Nodemailer, BullMQ, pino, helmet, PDFKit | React Native 0.76, React Navigation 7, Cashfree PG SDK, RN Firebase messaging, Sentry, Keychain, Zod |
| Size | ~57k LOC, 807 files | ~71k LOC, 434 files |
| Architecture | Clean Architecture / DDD: `domain → application → infrastructure → presentation` | Same layering: `domain → application → infra → presentation` |
| Shared | Both import **`@academyflo/contracts`** (envelopes, enums, fee math, audit taxonomy) | |

Both apps mirror the same ~20 feature domains (student, batch, attendance, staff, fees, subscription/payments, enquiry, event, expense, review, dashboard/reports, notifications, audit, account-deletion, academy, identity/auth). The mobile app is a thin client: domain logic and tenant isolation live server-side; mobile validates responses with Zod and renders.

## 2. API (`apps/api`) — NestJS backend

### 2.1 Layering & request lifecycle

```
HTTP request
  → main.ts middleware:  helmet → compression(>1KB) → RequestIdInterceptor (AsyncLocalStorage correlation id)
  → GlobalExceptionFilter (uniform ApiError envelope)
  → SanitizePipe + global ValidationPipe (class-validator DTOs)
  → Global guards (order):  RateLimitGuard → JwtAuthGuard → SubscriptionEnforcementGuard
  → Controller (@Roles RBAC, @CurrentUser, ParseObjectIdPipe)
  → Use-case (application layer; returns Result<T, AppError>)
  → Domain entity + rules (pure; optimistic-concurrency version CAS)
  → Repository port → Mongo adapter → MongoDB
  → Result → HTTP via result-mapper (ERROR_STATUS_MAP)
```

- **`domain/`** (78 files): pure aggregates (`User`, `Session`, `Academy`, `Student`, `Batch`, `FeeDue`, `Subscription`, …), value objects, domain rules, and repository **ports** (interfaces). No framework imports.
- **`application/`** (240 files): one folder per feature, each with `use-cases/` (the transaction script) + DTOs + ports. Use-cases return a `Result` monad; cross-tenant isolation is enforced **here** (`entity.academyId === actor.academyId`), not in repositories.
- **`infrastructure/`** (114 files): Mongo repositories + 26 schemas, Redis/in-memory cache, BullMQ queue, `@nestjs/schedule` crons, R2 storage (sharp resize), Cashfree gateway, Firebase/Nodemailer, PDFKit renderer, metrics, distributed job-lock, DB index verifier, super-admin seeding, tenant teardown.
- **`presentation/`** (155 files): HTTP controllers + the cross-cutting `common/` (3 global guards, logging interceptor, sanitize pipe, decorators, pagination DTO, result-mapper), health/metrics/profile/uploads/swagger.
- **`shared/`** (26 files): Zod-validated env config, DDD kernel (`Entity`, `UniqueId`, `Result`/`AppError`), pino logging port, IST date utils, PII redaction, image magic-byte validation.

### 2.2 Authentication & multi-tenancy model

- Owners self-signup; staff/parents are created by owners. Login by password or Google ID-token; super-admin has a **separate** login surface (`/admin/auth`).
- **Access token** = JWT carrying `{userId, email, role, academyId, tokenVersion}`. **Refresh token** = opaque, rotating, backed by a per-device **`Session`** record.
- `JwtAuthGuard` re-validates `tokenVersion` against the user's current value (via a Redis/in-memory auth cache) on every request — this is the **global revocation** mechanism (used by "disable academy login", force-logout, password reset).
- Tenant isolation is **application-layer**: every use-case resolves the actor's `academyId` server-side and checks ownership. Repositories deliberately expose unscoped `findById`/`deleteById` (documented), so isolation correctness depends on each use-case remembering to check. (See findings: a few repo methods — `bulkUpdateStatus`, gallery-photo `delete` — are unscoped and rely purely on caller trust.)

### 2.4 Cross-cutting infrastructure

- **Persistence:** 26 Mongo collections; a startup `IndexVerifierService` drops legacy indexes, runs idempotent backfills, and asserts a canonical `INDEX_SPEC`. A `TransactionService` propagates a `ClientSession` via AsyncLocalStorage; a slow-query profiler plugin logs slow ops.
- **Payments (Cashfree):** OWNER initiates an order priced by required tier; settlement via **signature-verified webhook** *or* server-side **poll-verification** against Cashfree's get-order API. Idempotency via compare-and-swap status transitions and a one-PENDING-per-academy partial unique index.
- **Notifications:** FCM multicast (with stale-token cleanup), transactional HTML email (Nodemailer + shared branded layout), and a BullMQ-scheduled delayed "student absent" push.
- **Scheduling:** crons for monthly dues generation, fee/overdue reminders, session purge, subscription-tier evaluation, and the account-deletion sweep. A Mongo-backed distributed **job-lock** guards most (but not all) crons.
- **Subscription tiers:** usage-based, derived from a **peak-of-cycle** active-student count (24h grace window prevents typo inflation; peak never decreases within a paid cycle so owners can't drop students to dodge an upgrade).
- **Storage:** Cloudflare R2 (sharp image resize) with a local-disk fallback.
- **Observability:** in-memory Prometheus-style metrics, pino structured logging, no-op error tracker.

### 2.5 API strengths

Consistent Clean-Architecture discipline, `Result`-monad error handling everywhere, optimistic-concurrency CAS on writes, defense-in-depth on the super-admin surface (role re-checked inside each use-case), webhook signature verification on raw bytes, late-fee config **snapshotting** so rates can't be retroactively re-priced, and a genuine CI gate suite (boundaries via dependency-cruiser, contract checks, index assertion).

## 3. Mobile (`apps/mobile`) — React Native app

### 3.1 Layering & data flow

```
Screen (presentation)
  → hook / use-case (application; returns Result<T, AppError>)
  → infra api adapter (e.g. studentApi) → shared api-client (infra/http)
  → policyFetch (timeout + retry) → API → unwrap {data} envelope
  → Zod validate at the infra boundary → typed domain model → state → render
```

- **`domain/`** (49 files): TS types + **Zod schemas** per feature (response validation source of truth).
- **`application/`** (105 files): framework-free use-cases + React hooks (`useStudents`, `useFees`, `useAttendance`, `usePaymentFlow`, …).
- **`infra/`** (54 files): per-feature HTTP adapters over the shared `infra/http/api-client`, plus Keychain token store, FCM adapter, RNFS file/PDF download, Sentry observability.
- **`presentation/`** (200 files): screens, ~20-component design system (`components/ui`), navigation, and 6 React contexts (Auth, Theme, Toast, Alert, FAB, Notification).

### 3.2 The shared HTTP client (`infra/http`)

This is the spine of the app. `api-client.ts` provides `apiGet/Post/Put/Patch/Delete`, holds the **access token in memory**, and persists the **refresh token in Keychain**. It does **proactive** refresh (decode-and-check expiry before a call) and **reactive** refresh (on 401, `tryRefresh` once then retry), per-request correlation ids, and `policyFetch`/`fetchWithTimeout` (30s AbortController). `error-mapper.ts` maps HTTP → domain `AppError`. (See findings: the `tryRefresh` merge deliberately does *not* refresh `user.status`, the error-mapper expects string `details` but the contract defines objects, and a couple of web/Hermes edge cases.)

### 3.3 Navigation model (role-gated)

A top-level **auth "phase"** state machine (`initializing → updateRequired → unauthenticated → needsAcademySetup → blocked → ready`) selects the tree:

- **AuthStack:** `Login`, `OwnerSignup`, `AcademySetup`, `ForgotPassword`
- **OwnerTabs** (bottom tabs): `Dashboard`, `Students`, `Attendance`, `Fees`, `More` — where `More` (MoreStack) hosts staff, reports, audit, reviews, enquiry, events, expenses, settings, subscription.
- **StaffTabs:** `Students`, `Attendance`, `Fees`, `More` (no Dashboard).
- **ParentTabs:** `Children` (ParentHomeStack), `Fees`/`Payments`, `More`.
- **BlockedStack** / **ForceUpdate** gates for disabled-academy / kill-switch states.

> Architectural note: several stack files (`BatchesStack`, `StaffStack`, `ReportsStack`, `ParentPaymentsStack` in places) export navigators that aren't mounted — the screens are actually hosted inside `MoreStack`. These exported navigators are dead (findings below).

## 4. Cross-cutting end-to-end analysis

### 4.1 Contract alignment (`@academyflo/contracts`)
Both apps share the API envelope (`ApiSuccess`/`ApiError`/`Paginated`), `AppErrorCode`, role/status/subscription enums, fee math (`computeLateFee`, `TIER_PRICING_INR`, `TIER_RANGES`), and audit taxonomy. **Divergences found:**
- `AppErrorCode` includes `RATE_LIMITED`, but the API's `ERROR_STATUS_MAP` omits it → would map to **HTTP 500 instead of 429**.
- The mobile error-mapper treats `ValidationErrorDetail` as a **string**, but the contract defines it as `{field, message, value?}` → field errors silently dropped.
- `SubscriptionSummary` is **not** in contracts at all; the API ships extra undeclared fields and mobile hardcodes `₹299`/tier ranges that duplicate (and can drift from) `TIER_PRICING_INR`.
- Notification `type` enum drift (see 4.4).

### 4.2 Auth & tenancy (end-to-end)
Login → JWT (in-memory) + refresh token (Keychain) → `tokenVersion`-gated `JwtAuthGuard` → per-use-case `academyId` checks. **Systemic risks:** (1) `tokenVersion` is **per-user, not per-session**, and refresh increments it unconditionally → one device refreshing invalidates *every other device* (refresh thrash). (2) Mobile `restore-session` checks `user.status` from Keychain, but refresh never updates `status` → a **server-deactivated user stays "ACTIVE"** on cold start. (3) Isolation lives entirely in use-cases; a few repo methods are unscoped by `academyId` and safe only by caller trust.

### 4.3 Payments (end-to-end)
Mobile initiates → API creates Cashfree order → checkout (native/JS SDK) → mobile polls `/status` with backoff; settlement via webhook *or* poll. **The webhook and poll paths are not equivalent:** the webhook cross-checks **amount + currency**; the **poll path checks amount only (subscription) or neither amount nor currency (parent fee poll)**. The `CashfreeGatewayPort.GetOrderOutput` lacks `orderCurrency`, so the poll path *structurally cannot* match the webhook's defense-in-depth. Idempotency (CAS transitions, partial unique index) is otherwise solid. The mobile Cashfree **fee-payment** path is dead code (manual UPI is the live flow).

### 4.4 Notifications (end-to-end)
Mobile requests permission → registers FCM token (`POST /device-tokens`) → API multicasts. **Broken route:** backend emits `data.type = 'PAYMENT_REQUEST'`, but the mobile `NotificationType` union only defines `'PAYMENT_REQUEST_PENDING'`; `parseRemoteMessage` blindly casts the string, `ROUTE_BY_TYPE['PAYMENT_REQUEST']` is `undefined`, and the tap lands nowhere. The unsafe cast means *any* future backend type silently breaks routing — no whitelist/fallback to `SYSTEM`.

## 5. Top recommendations (prioritized)

1. **Make `GET /students/:id/credentials` non-destructive** — it currently resets the parent password on every view and is an unthrottled reset oracle. Split into a read + an explicit, rate-limited `POST .../credentials/reset`.
2. **Wrap destructive/compliance flows in transactions** — owner account-deletion teardown and `academy-teardown.service` run ~20 sequential deletes with no transaction and no idempotent resume; a mid-way crash leaves a half-wiped tenant that re-runs hourly.
3. **Unify payment verification** — add `orderCurrency` to the gateway port and apply the same amount+currency check on both webhook and poll paths.
4. **Fix the metrics path** — allowlist `/api/v1/metrics` in `SubscriptionEnforcementGuard` (currently 403s) and fix the Prometheus exposition format in `basic-metrics.adapter` (currently unparseable).
5. **Fix the broken index assertion** — `INDEX_SPEC` collection names don't match 5 real (financial) collections, so the index gate is permanently noisy and masks genuinely missing indexes.
6. **Fix notification routing** — align the `PAYMENT_REQUEST` type and add a runtime whitelist with `SYSTEM` fallback in `parseRemoteMessage`.
7. **Repair the mobile destructive screens** — `InstituteInfoScreen` renders only its Save button and wipes bank/UPI details; it's also dead-routed. Delete it (PaymentMethods is the live editor) or restore its body.
8. **Make `tokenVersion` per-session** and refresh `user.status` on token refresh, so multi-device sessions don't thrash and deactivations take effect on the client.
9. **Add error+timeout safety to PDF/upload paths** — `pdfkit-renderer` never rejects on error (hangs the request); mobile gallery upload bypasses `policyFetch` (can hang forever).
10. **Push pagination/filtering into the DB** — many list endpoints (payment-requests, batch students, admin academies, unpaid dues) load whole collections and paginate in memory.
11. **Neutralize CSV formula injection** in the attendance CSV export (prefix leading `= + - @` / tab).
12. **Close the test gaps on security-critical paths** — review slice, enquiry isolation, `set-academy-login-disabled` cascade, and the entire payment-flow UI (its spec is stale and would fail).

## 6. Consolidated findings

*Grouped by severity, then by app. File paths are repo-relative. 267 total.*

### HIGH severity (18)


#### API

- **[bug]** `apps/api/src/application/account-deletion/services/deletion-strategy.ts`
  OwnerDeletionStrategy.execute is non-atomic and not retry-safe across a crash. It loops anonymizeAndSoftDelete over every academy user, then calls teardown.teardown(academyId); neither the loop nor the teardown is wrapped in a DB transaction (no getTransactionSession/startSession is opened anywhere in the strategy or ExecuteAccountDeletionUseCase, even though the Mongo repo's save() supports a session). If teardown fails partway, some users are already anonymized but markCompleted() never runs (request stays REQUESTED), so the next hourly sweep re-runs the full owner teardown against a partially-destroyed academy. There is no integration test covering owner teardown failure/partial-completion.

- **[security]** `apps/api/src/application/attendance/use-cases/export-monthly-attendance-summary-csv.usecase.ts`
  CSV formula injection. csvEscape() only quotes cells containing comma/quote/newline; it does NOT neutralize leading =, +, -, @ or tab. Student fullName is written directly into the first column (line 50-51). A student named e.g. '=HYPERLINK(...)' or '+cmd|...' produces an active formula that executes when an owner opens the exported CSV in Excel/Sheets. Prefix dangerous leading characters with a single quote (or wrap and prefix) before emitting.

- **[security]** `apps/api/src/application/student/use-cases/get-student-credentials.usecase.ts`
  GET /students/:id/credentials is a destructive, side-effecting GET: it generates a new temp password, hashes it, and overwrites the linked parent's password (parentUser.changePassword + userRepo.save) on every call, then returns the plaintext password in the JSON response (and embeds it in shareText). A GET mutating the parent account is unsafe-by-method (cacheable/prefetchable/retried), and any prior parent password is silently invalidated each time an owner merely views credentials, locking the parent out. It also lacks any throttling (unlike the photo/invite/document routes), so it is an unauthenticated-rate password-reset oracle for any OWNER/STAFF. Should be a POST (explicit reset) and rate-limited.

- **[perf]** `apps/api/src/application/subscription/use-cases/recompute-pending-tiers.usecase.ts`
  RecomputePendingTiersUseCase.execute() loads ALL academy ids (academyRepo.findAllIds(), unbounded) and runs EvaluateTierUseCase sequentially per academy. Each EvaluateTier issues 2 countDocuments queries plus a findByAcademyId plus (often) a save and up to two more reads for the owner email — i.e. ~5 queries per academy with no batching and no pagination. This is a classic N+1/unbounded-fan-out batch that scales linearly and unboundedly with tenant count. The same EvaluateTier is also driven by the hourly tier-peak-evaluation.cron, compounding load.

- **[bug]** `apps/api/src/infrastructure/database/index-spec.ts`
  INDEX_SPEC collection names do not match the real Mongoose `collection:` names for 5 critical (mostly financial) collections, so IndexVerifierService.verify() always reports their indexes as missing when INDEX_ASSERTION_ENABLED=true. Spec uses `feedues` (real `fee_dues`, lines 51-58), `paymentrequests` (real `payment_requests`, 59-63), `transactionlogs` (real `transaction_logs`, 64-74), `staffattendances` (real `staffAttendance`, 76-82), `auditlogs` (real `audit_logs`, 84-86). index-verifier.service.ts verify() looks up `connection.db.collection(collection)` by these wrong names; a non-existent collection either throws (caught → all its specs flagged missing) or returns no indexes. Result: the index-assertion quality gate is permanently noisy/broken for the revenue path, masking genuinely missing indexes on those collections.

- **[bug]** `apps/api/src/infrastructure/metrics/basic-metrics.adapter.ts`
  render() produces invalid Prometheus exposition for labeled series. The map key is `name{labels}`, so it emits TYPE/value lines like `# TYPE http_requests_total{method="GET",status="2xx"} counter` and `http_request_duration_ms{method="GET"}_sum`. Prometheus requires the metric family name (without labels) on the # TYPE line and the `_sum`/`_count` suffix BEFORE the label braces (`http_request_duration_ms_sum{method="GET"}`). It also emits one # TYPE line per label-set, duplicating the family TYPE. The output (exposed via presentation/http/metrics/metrics.controller.ts) is unparseable by a real scraper for the only two metrics the app emits (http_requests_total with method/status labels, http_request_duration_ms with method label).

- **[bug]** `apps/api/src/infrastructure/reports/pdfkit-renderer.ts`
  All four render methods (renderMonthlyRevenue ~L84, renderPendingDues ~L144, renderStudentMonthlyAttendance ~L275, renderMonthlyAttendanceSummary ~L356) resolve only on doc.on('end') and never attach doc.on('error', reject). If PDFKit errors mid-render (e.g. missing/corrupt NotoSans TTF asset, or a bad value), the returned Promise never settles, so the controller's StreamableFile path hangs the HTTP request until the upstream timeout and leaks the request. The sibling PdfGeneratorService.toBuffer correctly wires an error reject; this renderer does not.

- **[dead-code]** `apps/api/src/presentation/http/account-deletion/account-deletion.controller.ts`
  The cancel-by-token path is unreachable. CancelAccountDeletionUseCase.execute accepts {userId|cancelToken} and the repo implements findByCancelToken, a 32-byte cancelToken is generated and stored on every request, and the use-case comment says it is for users who 'follow the email link while logged out'. But the DELETE /account/deletion controller only ever calls cancelUseCase.execute({ userId: user.userId }); no HTTP route accepts a cancelToken. The deletion email's 'Cancel deletion' CTA points to a static URL (https://academyflo.com/delete-account, see account-deletion-template.ts) with no token, so a logged-out user has no way to cancel. The entire cancelToken generation, storage, unique index, and findByCancelToken branch are dead until a token-accepting route exists.

- **[bug]** `apps/api/src/presentation/http/common/guards/subscription-enforcement.guard.ts`
  The global SubscriptionEnforcementGuard breaks the Prometheus metrics endpoint. /api/v1/metrics is @Public() (JwtAuthGuard returns true WITHOUT setting request.user) but is NOT in ALLOWED_PREFIXES. The subscription guard runs next, finds no user.userId, and returns false (lines 50-56) -> 403 Forbidden before the controller's own token check ever runs. Result: GET /api/v1/metrics always 403s and metrics scraping is impossible. ALLOWED_PREFIXES omits '/api/v1/metrics' (lines 14-26). Fix: allowlist metrics, or have the guard honor IS_PUBLIC_KEY like JwtAuthGuard does.


#### MOBILE

- **[bug]** `apps/mobile/src/application/attendance/use-attendance.ts`
  First-view default-PRESENT auto-fill fires on off-schedule days, contradicting OffScheduleDayPrompt's stated guarantee.
